# 015-param-override-audit-preview

适配上游基线：`7c28993f6bd9e92616f3f578212577f8b7c40b45`。

## 1. 背景

参数覆盖审计 `other.po` 会记录操作及覆盖值。覆盖 `messages` 等对话字段时，完整提示词和消息内容会重复进入日志，增加日志存储与备份体积；仅在最终落库前截断，也无法避免审计格式化时先完整序列化长字符串。

## 2. 目标

- 新日志只保存有界的参数覆盖预览，继续使用 `po: string[]` 和现有操作文本格式。
- 实际参数覆盖仍完整执行，渠道 `param_override` 配置保持完整。
- 保持现有审计触发范围、预览去重和普通用户日志隐藏规则，不新增开关或 UI。

## 3. 行为规则

- 每个覆盖值最多保留前 200 个 Unicode 字符（Go rune）：字符串取原文前缀，对象和数组取紧凑 JSON 文本的前缀。短值原样保留，不切断 UTF-8 字符；内部 JSON 片段可以不完整，外层 `po` 仍是合法的字符串数组。
- `set ... = ...`、`prepend ... with ...` 等操作沿用原格式，不附加原始长度、截断标志或省略号。`replace` 和 `regex_replace` 从实际匹配与替换文本的第一个字符起截取，首尾空白也计入预览。
- 整个 `po` 数组的 JSON 序列化结果最多 1024 字节，预算包含数组结构、引号、逗号及 JSON 转义。整体预算可能进一步缩短最后一条值预览；操作类型和字段路径完整保留，连这些元信息也无法容纳时不再收集该条及后续审计。触及预算后停止收集后续审计，实际覆盖操作继续执行。
- `set` 覆盖为 JSON `null` 时，审计沿用 `<empty>`。剩余预算不足以记录完整标记时，保留操作和路径，标记按剩余空间截短。
- 预览重复时沿用现有去重逻辑；不同长值若生成相同预览，仍可能合并为一条审计，实际覆盖操作分别完整执行。
- 预览在审计值格式化源头生成，避免仅为审计完整序列化 `messages` 等数组或对象中的长字符串后再截断。
- `DEBUG` 模式同样受 200 字符和 1024 字节限制，不提供完整值审计的例外。
- 限制只作用于新生成的审计，不清理或改写历史日志，不需要数据库迁移。

## 4. 实现范围

- `relay/common/override.go`：接入审计值格式化及替换类 `from` / `to` 预览，保留实际参数覆盖及原操作文本合同。
- `relay/common/override_audit.go`：在源头生成有界预览，控制整体 JSON 字节预算并沿用预览去重逻辑。
- `relay/common/override_audit_test.go`：覆盖短值、Unicode、长对话内容、JSON 转义字节预算、去重、预算耗尽后继续覆盖及 DEBUG 模式。
- `scripts/verify_patches.sh`：将预览回归加入现有同组 Go 回归验证。
- 日志仍经 `RelayInfo.ParamOverrideAudit` 写入 `other.po`，沿用现有 `string[]` 格式；普通用户/API key 自助日志继续按 [013-hide-credit-system-prompts](013-hide-credit-system-prompts.md) 隐藏该字段。

## 5. 风险与兼容性

- 管理员对新日志查看已记录的预览；被截断或未收集的覆盖值无法从 `po` 还原，且日志不提供原始长度或截断状态。
- 审计预算耗尽后的操作不会出现在 `po` 中，不能把预览列表当作本次覆盖操作的完整清单。
- 预览仍可能包含渠道提示词片段，013 的客户日志过滤规则继续生效。
- 渠道配置、实际发往上游的完整参数及其他日志元数据不受影响。
